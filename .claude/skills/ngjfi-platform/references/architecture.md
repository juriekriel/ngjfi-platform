# The codebase — where things live

Next.js App Router + TypeScript + Tailwind, Supabase for data and auth, Netlify for
hosting and PR previews. `CLAUDE.md` in the repo root is the standing brief; this is the
map.

---

## Routes — `src/app/`

| Route | What it is |
|---|---|
| `/` | Landing — the five-door page |
| `/[org]` | **Respondent survey, community link.** For the young people a ministry already reaches |
| `/[org]/open` | The same instrument, fielded to everyone else. The gap between the two is the most useful number the Index produces — they must never become two different surveys |
| `/[org]/dashboard` | The org's own results |
| `/intelligence` · `/demo/intelligence` | Collab aggregate intelligence |
| `/access` | Sign-in (magic link, ministry website-domain verification) |
| `/join` | Waitlist / onboarding form |
| `/tour` | Guided walkthrough — renders the *real* components |
| `/learn` | Explainer, includes the DFW pilot table |
| `/build` · `/build/wireframes` | Console and tier wireframes |

`/[org]*` routes are server-rendered on demand; the rest are static.

## The model — `src/lib/`

| File | Responsibility |
|---|---|
| `scoring.ts` | **The scoring engine.** Small pure functions, well tested. The model of the codebase — read it first to understand the domain |
| `instrument.ts` | Loading and interpreting the versioned instrument config |
| `branching.ts` | Adaptive question branching |
| `model.ts` | Chart primitives and design tokens — `EMERALD`, `NAVY`, `TIER_TINT`, `heat()`, `delta()`. All colour here is `var(--c-*)` references, never hex |
| `sample.ts` | Derives every sample figure from the instrument JSON **at render time**. Not fixtures |
| `supabaseClient.ts` | Browser Supabase client (anon key, protected by RLS). Returns `null` when env vars are missing so the UI shows a setup notice instead of crashing |

**The scoring engine is duplicated in SQL.** If you change scoring logic, update **both**
`src/lib/scoring.ts` **and** the SQL `ngjfi_normalize` in `supabase/migrations/`, and add a
case to `tests/scoring.test.ts`. Getting these out of step is the worst bug available here.

## Components — `src/components/`

| Path | Notes |
|---|---|
| `survey/Survey.tsx` | Survey container. **Queries `organisations` and `campaigns` from the browser on mount** — that browser-side query is also why the Supabase project reads as idle when nobody is on the site |
| `survey/QuestionCard.tsx` | One question. Shared by the live survey, the landing page and `/tour` |
| `index/Figures.tsx` | The numbered figures. Also shared across demo and product |
| `index/IntelligenceView.tsx` | Collab aggregate view |
| `console/SurveyWizard.tsx`, `console/Bands.tsx` | Admin console |
| `site/Chrome.tsx` | Masthead, footer, site furniture |

`QuestionCard` and `Figures` are the two components the demo and the product **share**.
Never fork them "just for the demo" — `tests/sample.test.ts` fails the build if the demo
starts diverging from the product.

## Data and design tokens

- `src/data/instrument.v1.json` — **single source of truth** for items, scales, tags,
  reverse flags, translations. Edit here, then `npm run db:seed`
- `src/data/instrument.v0.json` — archived, not deleted. Responses bind to the version they
  were captured under
- `src/data/history.ts` — instrument version history
- `src/app/globals.css` — the `:root` block: **every colour in the platform**
- `tailwind.config.ts` — maps token names onto those CSS variables via
  `rgb(var(--c-*) / <alpha-value>)`, so opacity modifiers keep working. `borderRadius` and
  `boxShadow` deliberately collapse to nothing, so rounded cards and shadows cannot be
  written even by accident

## Database — `supabase/`

| File | Purpose |
|---|---|
| `migrations/000N_*.sql` | The schema, in order. Monotonic numbering. **Claim your number in chat first** |
| `bootstrap.sql` | Generated by `npm run db:bootstrap` — every migration in order, one paste to stand up a fresh project. Excludes demo seeds |
| `seed.sql`, `seed_demo_data.sql`, `seed_demo_world.sql` | Seeds |
| `delete_demo_data.sql` | Removes the ~79k synthetic demo responses before official testing |
| `config.toml` | Local Supabase config |

**Two data spaces.** `is_demo = false` is live and the only thing `/intelligence`
publishes; `is_demo = true` is the sandbox. The split is enforced inside the SECURITY
DEFINER functions and by a trigger — not by remembering a `WHERE` clause. Check with
`select public.data_space_report();` before any announcement.

## CI and automation — `.github/workflows/`

- **`ci.yml`** — on every PR: `npm ci`, typecheck, test, build. The `build` check is
  required by the ruleset; the merge button stays disabled until it's green.
- **`supabase-keepalive.yml`** — Mondays 06:17 UTC plus manual dispatch. Loads the survey
  route in headless Chromium so the Supabase free tier registers activity. The app queries
  the database from the *browser*, so a plain HTTP request would never touch it and the
  project reads as idle even while the site is up. No secrets: the anon key already ships in
  the deployed bundle. It also works as an end-to-end uptime check — if it goes red, the
  survey route has stopped reaching the database.
