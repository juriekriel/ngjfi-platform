# Release notes — team tiers, one link, J12 only, v5 locked (migrations 0043–0045)

## Apply, in order
1. Merge the PR(s); CI green; review the Deploy Preview.
2. Apply migrations `0043_org_team_tiers.sql`, `0044_one_link_and_survey_versions.sql`,
   `0045_instrument_lock.sql` (Supabase SQL editor or `npm run` publish flow — see docs/PUBLISHING.md).
3. `npm run db:seed` — pushes v5's new `item_sets`, adopts, and **locks v5**.
4. Confirm: `select instrument_status();` → v5 `active`, `locked_at` set, `item_sets` `["full","j12"]`.

## What changes for people
| Who | Before | After |
|---|---|---|
| Ministry staff with a matching email domain | Anyone could claim and become an admin | First person claims; everyone else needs an invite |
| Organisations with several admins | All admins | Earliest stays **Org Administrator**; others become **Coordinators** |
| Facilitators | Read-only settings | **Coordinators** — same dashboard access |
| Org Administrator | — | *Team & access*: add up to 5 coordinators by email, remove, hand over |
| Respondents on `/[org]/open` | Public campaign | Redirected to `/[org]` |
| Survey settings | Fixed full survey | **Survey version**: Full (~6 min) or J12 only (~5 min); rooms can override |

## Known follow-ups
- The server doesn't yet refuse an answer outside a session's item set (the phone never asks it).
- Invitation emails reuse Supabase's magic-link template (lands on `/build`, which accepts the invite).
- Adopting a future version fails for any campaign whose item set that version doesn't define — by design.
